# Implementation collaboration contract

Python package lives in src/modelbuilder. Shared API is POST /v1/operations/{operation}, JSON payload, Bearer token. OperationService.invoke(operation: str, payload: dict, actor: Actor) -> dict is the only business entrypoint. GET /v1/catalog supplies operation names, JSON input schemas, scope and description. GET /health is unauthenticated; all resource operations require configured identity. Error body: {error:{code,message,details}}, HTTP409 conflicts. Metadata keys are snake_case. Recipe responses expose recipe_id, project_id, revision, digest and normalized fields. A recipe body uses schema_version="0", nodes/edges and required specification fields. Edges use source_node/source_port/target_node/target_port; typed ports use {name,type}. Implementers coordinate exact schemas through models.py and recipe.py. Do not create alternate logic in UI/MCP.

Ownership: service worker models.py/store.py/service.py/auth.py/api.py and service tests. Recipe worker recipe.py and recipe schema/security tests. Execution worker backend/ and fixtures plus integration tests. MCP worker mcp_server.py plus stdio/API contract tests. IDE worker packages/ide_feature only plus its unit tests. Distribution worker distribution/ and scripts/build_ide.sh/smoke_ide.sh plus GUI tests. Root owns pyproject/locks/bootstrap/test_all/CI/docs aggregate and commits. Workers do not git commit/stage; root commits coherent increments.

Service execution boundary: injectable backend exposing invoke(operation,payload,actor) or agreed small methods; coordinate directly before implementation. Backend authoritative IDs must remain visible. Application operations correlate, do not compete with ZenML records. Remote spend/publish disabled; untrusted code execution fails closed unless a real supported isolation boundary passes. Trusted repository-owned fixtures may run under explicit execute scope. No Biff modifications, paid compute, public releases, secret commits or core Code-OSS patches.
